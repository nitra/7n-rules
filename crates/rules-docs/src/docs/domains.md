## Огляд

Резолв документаційних доменів репозиторію — порт `domain-resolver.mjs`.  Домен визначає МАНІФЕСТ, а не тека: ідентичність `<ecosystem>:<canonical-name>` не залежить від шляху, тож переміщення пакета не створює нового домену. Невалідний маніфест чи повторена ідентичність лишаються ДІАГНОСТИКОЮ — fallback-ідентичності з шляху не буває, бо вона тихо роздвоїла б знання про той самий пакет.

## Публічний API

- Domain — Документаційний домен.
- Diagnostic — Блокувальна діагностика резолвера.
- ResolvedDomains — Результат резолву.
- canonical_domain_name — Канонічна назва пакета за правилами екосистеми — порт `canonicalDomainName`.  Python нормалізується за PEP 503 (`._-` → `-`, нижній регістр), composer — регістром; npm і cargo вже визначають канонічну ідентичність самі, тож їм потрібне лише обрізання пробілів.
- resolve_documentation_domains — Резолвить усі маніфест-backed домени репозиторію — порт `resolveDocumentationDomains`.  # Errors Помилка обходу файлової системи; невалідні маніфести помилкою НЕ є — вони стають діагностиками.
- resolve_domain_for_path — Домен-власник шляху — порт `resolveDomainForPath`.  Перемагає НАЙГЛИБШИЙ вкладений корінь: файл у вкладеному пакеті належить саме йому, а не батьківському репозиторію.

## Гарантії поведінки

- Власних операцій запису (ФС/БД) у файлі немає; виклики імпортованих модулів можуть писати.
- Містить локальні fail-safe гілки; інші помилки можуть поширюватися назовні.
- Деякі локальні fail-safe гілки повертають порожнє значення (напр. `null`) замість винятку.

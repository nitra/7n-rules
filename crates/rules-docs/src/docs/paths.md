## Огляд

Спільні path-інваріанти виявлення джерел — порт `domain-paths.mjs`.

## Поведінка

to_posix повертає той самий шлях у POSIX-формі, щоб подальші перевірки працювали однаково на різних платформах.

is_within приймає лише шляхи, що належать кореню або лежать усередині нього; вихід за межі кореня, включно з варіантами з батьківським переходом чи чужим коренем, дає `false`. Перевірка є строга щодо меж доступу й використовується як останній бар’єр перед читанням.

nested_domain_ignores повертає впорядкований набір ignore-шляхів для вкладених доменів, щоб батьківський домен не забирав собі джерела дочірнього. Шляхи, що вказують на сам корінь або виходять назовні, у результат не потрапляють.

## Публічний API

- to_posix — Платформний шлях у стабільній POSIX-формі.
- is_within — Строге входження шляху в корінь — порт `isWithin`.  Саме строге: рівність кореню теж рахується входженням, а от вихід за нього (`..`) чи абсолютний шлях — ні. Це остання перевірка перед читанням файла, і саме вона ловить symlink-втечу.
- nested_domain_ignores — Ignore-патерни для вкладених доменів — порт `nestedDomainIgnores`.  Вкладений домен документує СЕБЕ: якби батьківський домен теж читав його джерела, той самий код отримав би дві різні проєкції знання.

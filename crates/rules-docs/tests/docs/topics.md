## Огляд

Дзеркальний набір тем — сценарій-у-сценарій із `tests/topic-discovery.test.mjs`, плюс звірка ідентичностей із живим JS.  Звірка тут не формальність: ID теми — це хеш замикання, і будь-який дрейф (порядок ключів у хешованому JSON, обрізка до 24 символів, сортування) тихо перейменував би ВСІ вже опубліковані теми.

## Поведінка

Спирається на `js-topics.json`: результати мають збігатися з еталонними ID, а розбіжність у формі або складі тем означає зміну зовнішнього контракту.

Порожній або неповний граф не дає хибних тем; недосяжні вузли та ребра без evidence не додають досяжності й не змінюють набір результатів. Вихідні ідентичності мають лишатися стабільними для однакового замикання, навіть якщо змінюється відображуване ім’я публічного входу.

Аліаси мають зводитися до канонічної теми; якщо кілька публічних входів ділять одне замикання, вони зливаються в одну тему збереженням попередніх ID як aliases. Різні замикання не можуть зливатися в одну тему, інакше втрачається межа між окремими сценаріями домену.

**Status:** Accepted
**Date:** 2026-07-31

## Context and Problem Statement

`git-reconcile` може знайти локальні worktree, stash і branch, які більше не
мають open PR та не заблоковані через `git worktree lock`. Просте локальне
видалення таких джерел є незворотним для користувача: stash і незакомічені
зміни worktree не мають надійного remote ref, а локальний опис branch або
metadata `mt worktree` не передаються через `git push`.

Потрібен lifecycle, який спочатку робить точний стан відтворюваним в `origin`,
а потім прибирає локальні артефакти. Remote archive має нести машинно-читаний
контекст, щоб незалежний garbage collector міг через 45 днів безпечно очистити
лише власні тимчасові refs.

## Considered Options

- Видаляти локальні refs одразу після класифікації reconcile.
- Зберігати пояснення у `git branch --edit-description` або metadata
  `mt worktree`.
- Пушити початковий ref без окремого metadata commit.
- Створювати `tempo/*` archive branch з окремим metadata commit поверх
  збереженого стану.
- Залишити реалізацію lifecycle у JS-оркестраторі.
- Реалізувати lifecycle як Rust-компонент на Gix, лишивши JS лише наявною
  оркестрацією та presentation-result контрактом.

## Decision Outcome

Chosen option: "`origin/tempo/git-reconcile/*` з metadata commit, Rust + Gix,
WASM harness", because
Git пушить commits і refs, але не локальний `.git/config`, де зберігаються
branch descriptions та metadata worktree. Commit у remote archive робить
причину й інструкцію відновлення доступними з будь-якого clone. Rust + Gix
надає один типобезпечний execution layer для refs, worktree та stash замість
розподіленої shell/JS-логіки з різними failure modes. Сам skill є
WASM-компонентом, що володіє state machine оркестрації та LLM cascade;
JS compatibility adapter не створюється.

Для кожного кандидата Rust-компонент створює branch за формою
`tempo/git-reconcile/<YYYY-MM-DD>/<kind>-<slug>-<sha12>`. Вона містить точний
стан джерела та окремий metadata commit поверх його tip. Для dirty worktree і
stash цей стан спочатку materialize-иться в archive commit, включно з
untracked files. Metadata commit додає `.git-reconcile/archive.json` і
`ARCHIVE.md`.

Локальне очищення дозволене лише після того, як archive branch успішно
запушено й перевірено безпосередньо в `origin`: remote ref існує, manifest
читається, його schema та source OID валідні, а archive відтворюється у
тимчасовому checkout. Будь-яка помилка означає `keep`; cleanup не виконується.

WASM harness повертає Rust host-у лише типізовані declarative effects і після
кожного результату продовжує власну state machine. LLM-виклик — effect із
tier (`min` або `max`), bounded facts, schema та idempotency key; host виконує
transport, schema validation, checkpoint і повертає event компоненту. Git
effects (`repo.inventory`, `archive.create`, `archive.verify-origin`,
`repo.cleanup`, `pr.create`) виконує виключно trusted Rust host через
Gix/`mt-core`; WASM-компонент не отримує shell, довільний `git` або network
access.

Кандидатами автоматичного архівування є всі локальні branch, worktree та stash
репозиторію, для яких немає open PR і немає `worktree lock`. Поточний worktree
процесу не є кандидатом як технічний інваріант. Інші unlocked worktree можуть
бути архівовані та прибрані локально після remote verification.

### Consequences

- Good, because локальний Git-стан не видаляється, доки його незалежна remote
  копія не перевірена.
- Good, because пояснення, source identity і TTL є versioned Git-даними, а не
  clone-local configuration.
- Good, because порядок deterministic phase-ів, LLM `min → validation → max`
  fallback і рішення `keep/archive/pr` належать portable skill artifact, а не
  окремому JS runtime.
- Good, because окремий garbage collector може fail-closed обробляти лише
  `tempo/git-reconcile/*` із валідним manifest та простроченим `deleteAfter`.
- Bad, because кожен archive створює додатковий remote branch і metadata
  commit до завершення retention period.
- Bad, because materialization stash або dirty worktree в commit змінює форму
  локального стану; restore має відтворювати payload, а не обіцяти тотожний
  reflog/stash identity.
- Neutral, because GC є окремим компонентом: ця домовленість визначає його
  protocol, але не реалізує scheduler чи remote deletion.

## More Information

Мінімальний manifest має бути schema-versioned і містити щонайменше:

```json
{
  "schemaVersion": 1,
  "kind": "worktree",
  "source": { "ref": "feature/example", "oid": "<full-oid>" },
  "baseOid": "<full-oid>",
  "reason": "no-open-pr-and-no-worktree-lock",
  "createdAt": "2026-07-31T00:00:00Z",
  "deleteAfter": "2026-09-14T00:00:00Z",
  "restore": "git switch --track origin/tempo/git-reconcile/..."
}
```

GC працюватиме лише у dry-run за замовчуванням і видалятиме ref, лише якщо:

1. ref належить namespace `tempo/git-reconcile/`;
2. manifest існує й проходить schema validation;
3. `deleteAfter` минув;
4. ref не використовується open PR.

Відсутній або невалідний manifest, недоступність GitHub/open-PR перевірки чи
помилка Gix-операції є причиною пропустити ref, а не видаляти його. Команда
restore і детальний `dry-run` report входять до майбутнього execution
контракту.

WIT-контракт має додати домен `repository-lifecycle` із resumable transitions:
`start(request) -> transition` та `resume(checkpoint, host-event) ->
transition`. `transition` містить наступний checkpoint, progress/log records,
typed effects або terminal summary. Це одразу є канонічним Rust CLI/NAPI
шляхом; JS runtime або JS compatibility adapter не входять до архітектури.

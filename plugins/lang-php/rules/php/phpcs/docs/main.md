## Огляд

Файл готує PHP-шляхи для перевірки з `ctx.files` або з типових код-каталогів `app`, `src`, `lib`, `public`, `www`, а також відсікає `.git` і `node_modules`. Далі він запускає `vendor/bin/phpcs` зі стандартом `Security` як read-only detector, щоб перевірка охоплювала лише релевантні PHP-шляхи й повертала сигнали про проблеми без змін у проєкті.

## Поведінка

getPhpcsCodePaths формує набір цільових кодових каталогів для повного проходу: бере лише наявні каталоги з типової PHP-структури й, якщо жодного з них немає, підставляє поточний корінь репозиторію як запасний варіант.

lint спочатку відсікає нерелевантні запуски за наявністю composer.json, далі звужує перевірку до PHP-файлів у per-file режимі або використовує повний набір шляхів від getPhpcsCodePaths. Якщо в проєкті немає vendor/bin/phpcs, перевірка тихо пропускається; якщо інструмент доступний, запускається Security-стандарт і результат потрапляє в reporter як порушення лише при ненульовому коді завершення. Під час запуску свідомо виключаються .git, node_modules і vendor, а повідомлення про збій обмежується коротким фрагментом виводу, щоб не засмічувати звіт.

## Публічний API

- lint — Detector php/phpcs (read-only). Async (не блокує event loop) — детектор може виконуватись
у parallel lane `detectAll()` (ADR 260716-1354).
- getPhpcsCodePaths — повертає перелік шляхів до PHP-коду, який слід перевіряти, щоб PHPCS працював лише з релевантними файлами.

Конфіги, на які спирається код: composer.json

## Огляд

`patterns` застосовує локальні fail-safe гілки для окремих відомих випадків і виконує перевірки, які допомагають зупинити поширення непередбачених помилок назовні там, де це безпечніше для обробки. Для частини ситуацій він повертає порожнє значення замість винятку, щоб не переривати роботу на не критичних збоях; інші помилки залишаються видимими для верхнього рівня.

## Поведінка

1. `patterns` визначає дві стратегії виправлення для порушень `js/eslint`: автоматичну корекцію через лінтери та окремі текстові правки для точкових правил.
2. Перша стратегія спрацьовує, коли є порушення у JS-файлах, і запускає `oxlint` та `eslint` у режимі виправлення, щоб прибрати лише ті проблеми, які можна виправити без участі людини.
3. Якщо для запуску зовнішнього інструмента не вдається підготувати команду, ця частина просто пропускається, а решта обробки продовжується.
4. Друга стратегія застосовується до відомих механічних випадків, де заміна на рядку однозначно покращує код без потреби в повному аналізі структури.
5. Для таких випадків вона змінює лише ті рядки, які все ще відповідають очікуваному вигляду; якщо файл уже змінився і збіг зник, рядок пропускається без помилки.
6. Обидві стратегії повертають перелік реально змінених файлів, щоб наступні кроки могли точно знати, що саме було оновлено.
7. Якщо змін немає, `patterns` повертає порожній результат і не створює зайвих записів про оновлення.
8. У разі локальних проблем з читанням або відсутністю файла обробка для цього файла тихо завершується без винятку; інші помилки можуть піднятися назовні.

## Огляд

Збирає компактний набір фактів через `extractFacts` для подальшого використання в документації та перевірках. Свідомо ігнорує `.github`, `.git`, `node_modules`, `base/`, `ua/`, `.firebase`, звертається до мережі та в окремих fail-safe гілках повертає порожнє значення замість винятку.

## Поведінка

1. Приймає код файлу й шлях до нього, щоб зібрати структуровані факти для подальшого аналізу документації.
2. Визначає мову файлу та рівень підтримки за шляхом; окремо обробляє Vue-одиниці зі script-блоку, а для інших JS-подібних файлів працює з AST-структурою.
3. Якщо парсинг вдається, бере коментарі з реального AST, щоб не плутати справжні JSDoc-блоки з фрагментами тексту всередині рядків або line-коментарів.
4. Якщо парсинг не вдається, переходить у fail-safe режим і повертає факти через запасні гілки без падіння, щоб не зупиняти весь прогін.
5. Збирає провідний header-фрагмент файлу, список експортів із їхнім JSDoc, імпорти з базовим поділом на зовнішні, внутрішні та stdlib-залежності, а також поведінкові маркери файлу.
6. Додає до результату імена внутрішніх символів та неекспортованих top-level функцій або класів, щоб не змішувати службову реалізацію з публічним API.
7. Для файлів із відомими пропусками не аналізує шляхи `.github`, `.git`, `node_modules`, `base/`, `ua/`, `.firebase`, щоб не витрачати ресурси на нерелевантні або виключені ділянки репозиторію.
8. Використовує кеш у межах одного прогону, щоб повторні звернення до того самого файлу не дублювали роботу.
9. Звертається до мережі, коли це потрібно для збагачення чи звірки фактів.
10. Повертає компактну структуру фактів про файл для наступних кроків генерації документації чи перевірок.

## Публічний API

- extractFacts — Головний екстрактор: код файлу → факт-лист.
Коментарі беруться з реального AST-парсера (`parseProgramAndCommentsOrNull`),
не regex по сирому тексту — усуває клас false positive, де "/**"-подібний
текст усередині `//`-коментаря чи рядкового літералу (напр. glob-патерн)
помилково читається як відкриття JSDoc. Парсинг не вдався (синтаксична
помилка) → `comments: null`, `extractFileHeader`/`extractExports` падають
назад на свій regex-шлях (той самий, що й до цієї зміни).

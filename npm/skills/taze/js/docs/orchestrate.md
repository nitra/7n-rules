## Огляд

Файл керує запуском оновлення залежностей через завантаження провайдерів, виконання раннерів і зведення результатів у читабельний звіт. У межах одного прогону використовується кешування, а локальні fail-safe гілки дозволяють продовжити обробку там, де це можливо, тоді як частина помилок може поширюватися назовні.

## Поведінка

`runTazeOrchestrator` починає з визначення набору екосистем і далі веде прогін як послідовність ізольованих проходів, де помилка в одному пакеті або одній екосистемі не скидає інші результати. Для цього він спирається на плагіни з `package.json` і на локальні підказки з `.n-rules.json`, а під час одного запуску тримає проміжний стан і кешовані дані всередині прогону.

`loadPluginTazeProviders` збирає доступні провайдери екосистем у єдиний список, відкидаючи биті або непридатні плагіни без зриву всього процесу. Саме цей список стає джерелом для наступних кроків оркестрації, тому якість і повнота прогону залежать від того, що вдалося завантажити на старті.

`callRunner` запускає один ізольований пакет роботи для вибраного раннера й повертає нормалізований результат, який далі використовують і для змін у кодовій базі, і для звіту. Для `pi` текст результату приходить через стрім, а для `cursor` і `codex` — напряму з bridge-інтеграції; тьєр `avg` зберігає паритет з pi-гілкою без підхоплення локального CLI-конфіга машини.

`formatReport` збирає фінальний Markdown-звіт із накопичених результатів усіх екосистем без окремого LLM-кроку для самого звіту. `runTazeOrchestrator` передає сюди дані після завершення всіх проходів, і на виході формується стабільний підсумок по всьому прогону, де екосистеми без маніфестів просто не потрапляють у секції.

## Публічний API

- callRunner — Диспетчер одного ітеративного виклику на обраний раннер. `pi` — вбудований
pi-агент (`@7n/llm-lib/agent-skill`; текст перехоплюється через `deps.out`,
бо `runAgentSkill` не повертає його напряму — лише стрімить у stdout).
`cursor`/`codex` — napi-міст ACP (`@7n/llm-lib/acp`; текст — прямий return,
idle-timeout і видимість прогресу вже вбудовані в сам міст). Тір `avg`
(рішення И/Ф3, задача T7) — паритет з pi-гілкою: `runAcpAgent` резолвить
tier→env/args/post-session-config у Rust, а не бере модель з персонального
CLI-конфіга на машині.
- loadPluginTazeProviders — Завантажує EcosystemProvider-и з активних плагінів проєкту: `.n-rules.json`
(або автодетект за файловими сигналами — `pyproject.toml` → lang-python) →
`resolveSlotGraph` (плагін доставляється автоматично при першому запуску, allowInstall
за замовчуванням) → `taze.provider@1` contributions → default-експорт кожного валідується
`assertEcosystemProvider` (spec 2026-07-27-universal-plugin-slots-lang-php-extraction §5.1.5).
Битий плагін (нема ресурсу/невалідна форма) — warning і пропуск, не провал прогону.
- formatReport — Компонує підсумковий звіт (крок 8 SKILL.md) детерміновано з результатів
ітерацій — без окремого LLM-виклику для самого звіту. Усі екосистеми
(включно з npm/bun — плагін `@7n/rules-lang-js`, фаза 5a) — рівноправні
секції; екосистема без manifests — тиша.
- runTazeOrchestrator — Оркеструє taze: чистий цикл по EcosystemProvider-ах (кроки 1-3/7/8 —
детерміновано в провайдері, кроки 4-6 — по одному ізольованому виклику
`callRunner` на кожен major-запис) замість одного величезного непрозорого
ходу на весь монорепо. Ядро — двигун без мовної специфіки (фаза 5a spec):
ВСІ екосистеми, включно з npm/bun (`@7n/rules-lang-js`), приходять з
плагінів (extension-point `taze`). Падіння одного пакета/однієї екосистеми
не втрачає прогрес по інших.

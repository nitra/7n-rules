Ця функція обробляє порушення, пов'язані з документацією, генеруючи застарілі або відсутні файли. Вона також очищує документацію, яка залишилася після видалення вихідного коду.

## Поведінка
1. Визначається індекс тест-доказів для поточного робочого каталогу.
2. Фільтруються порушення, які не є "сирітськими документами" (`orphaned-doc`), щоб визначити список застарілих файлів.
3. Для кожного застарілого файлу реєструється його шлях як стійка запис.
4. Якщо знайдені застарілі файли, виконується пакетна генерація документів із використанням відповідної моделі та рівня, обмежуючись часовим лімітом, встановленим у контексті.
5. Фільтруються порушення, які є "сирітськими документами" (джерело видалено).
6. Для кожного такого сирітського документа реєструється його початковий стан для забезпечення можливості відкату.
7. Виконується очищення від сирітських документів у каталозі.
8. Повертається список усіх файлів, до яких було застосована зміна.

## Гарантії поведінки
* Застарілі документи, після їх генерації, отримують новий контрольний суму (CRC) та вважаються актуальними, що запобігає їх повторній генерації.
* У разі збою, стійкі записи (згенеровані документи) залишаються, оскільки їхнє додавання є кінцевим станом, що дозволяє частковому відновленню прогресу.
* Видалення сирітських документів здійснюється звичайним механізмом відкату.
* Пакетна генерація зупиняється, якщо перевищено 80% від загального часового ліміту рунгу, щоб уникнути перевантаження наступних операцій.

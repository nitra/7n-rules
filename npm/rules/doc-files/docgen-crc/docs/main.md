## Огляд

Файл описує правила читання, побудови й перевірки frontmatter Markdown-документації: CRC джерела, модель, tier і оцінку якості. Він потрібен, щоб визначати стан документації — відсутня, застаріла через зміну source CRC або актуальна за записаними метаданими.

## Поведінка

Документація прив’язується до evidence через стабільний CRC. `documentationCrc` формує значення для джерела: без тестового індексу воно відповідає CRC самого source, а за наявності пов’язаних тестів включає також їхні шляхи й вміст. `crc32` забезпечує єдиний формат такого відбитка.

Frontmatter є спільним станом між генерацією, читанням і перевіркою документації. `buildDocFrontmatter` створює OKF-сумісні метадані з посиланням на source, CRC, моделлю, tier і якістю, а `stampDoc` замінює будь-який попередній блок на актуальний. `parseDocFrontmatter` уніфікує читання старих і нових документів: відсутні необов’язкові поля повертаються як порожні або null-значення.

Якість документації зберігається разом із CRC, щоб наступні перевірки могли повторно використати результат оцінювання. `QUALITY_THRESHOLD` задає поріг прийнятності, а issue-дані у frontmatter зберігаються як короткі коди, придатні для YAML.

`readDocCrc`, `readDocQuality`, `readDocModel` і `readDocTier` читають окремі частини frontmatter із наявної md-доки та повертають null-значення, коли документа немає або потрібне поле відсутнє. Це зберігає сумісність із документами, створеними до появи полів моделі, tier або якості.

`staleness` порівнює поточний CRC evidence з CRC, записаним у документації. Якщо md-файл відсутній, результат позначає документацію як missing; якщо CRC відрізняється — як crc-mismatch; збіг означає, що документація актуальна щодо поточного source і пов’язаних тестів.

## Публічний API

- QUALITY_THRESHOLD — Поріг degraded: дока зі `score` нижче вважається неякісною.
- crc32 — CRC32 вмісту у hex (8 символів, з провідними нулями). Делегує у нативний
`node:zlib.crc32` — без ручної бітової арифметики.
- documentationCrc — CRC повного evidence для файлової доки. Без повʼязаних тестів лишається
back-compatible CRC самого source; за наявності тестів додає їхні шляхи та
вміст, тому зміна usage-сценарію детерміновано робить доку stale.
- parseDocFrontmatter — Парсить frontmatter файлової доки. Без блоку — `data:null` і `body` дорівнює входу.
Поля `model`/`score`/`issues` опційні (back-compat зі старими доками): без них —
`model:null`, `score:null`, `issues:[]`.
- buildDocFrontmatter — Будує OKF-сумісний frontmatter-блок: OKF-поля верхнього рівня + вкладений `docgen:`
з CRC/model/quality. OKF-поля виводяться першими, щоб будь-який OKF-парсер міг їх
читати незалежно від `docgen:`-простору назв.
- stampDoc — (Пере)штампує frontmatter у md-доку: знімає наявний блок і додає свіжий.
- readDocCrc — CRC, збережений у frontmatter доки; `null` — доки немає або CRC відсутній.
- readDocQuality — Якість, збережена у frontmatter доки.
- readDocModel — Модель-генератор, збережена у frontmatter доки; `null` — доки немає або поле відсутнє
(старі доки до введення `model`).
- readDocTier — Tier моделі-генератора зі frontmatter доки; `null` — доки немає або поле відсутнє.
- staleness — Стан застарілості доки відносно evidence: source + повʼязані тести.
`missing` — доки немає; `crc-mismatch` — evidence CRC ≠ CRC у доці; інакше свіжа.

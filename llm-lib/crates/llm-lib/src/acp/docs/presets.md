## Огляд

`TierPreset` задає пресет для кожного `super::AcpAgentKind`: як `Tier::Min/Avg/Max` перетворюється на конкретний спосіб резолвінгу моделі — `env` для Codex, `extra-arg` для Cursor або `post-session config` для Pi — і який UI-лейбл показувати користувачу. `label` і `tier_preset` живуть тут, у Rust-пресетах, щоб не дублювати їх у JS. Результат використовується як готовий preset для зливання `env` і `extra_args` у `super::session::SessionOptions`, а `post_session_config` передається як є, без повторного розгалуження по kind-у.

## Поведінка

`TierPreset` є спільним контейнером для результату вибору тіру: він зводить у один формат UI-лейбл і рівно один спосіб застосування — або `env`, або `extra_args`, або `post_session_config`. Це дає змогу споживачам брати готовий preset без повторної розгалужувальної логіки за kind-ом і передавати далі лише заповнену частину, не змішуючи способи резолвінгу між собою.

`label` повертає стабільну назву самого ACP-агента для інтерфейсу, незалежну від тіру. Вона використовується як базова людозрозуміла ідентифікація, а не як технічний ключ, тому лишається сталою для кожного kind-у.

`tier_preset` приймає абстрактний tier і перетворює його на конкретний preset для відповідного ACP-kind. Для Codex результат іде через `CODEX_CONFIG` із JSON-значенням моделі; для Cursor — через `--model`; для Pi — через post-session зміну конфігу, що спирається на локальні `models.json`-описання провайдерів, зокрема для `litellm` через `https://llm.7n.ai/v1/`. Усі три гілки використовують один і той самий контракт результату, тому наступний шар може застосувати preset без знання деталей джерела моделі.

## Публічний API

- TierPreset — Результат резолвінгу `AcpAgentKind × Tier`.
- label — Людинозрозумілий лейбл самого агента (рішення Д), незалежний від тіру.
- tier_preset — Резолвить `tier` у [`TierPreset`] для цього kind-у (рішення Б/Ж/З/З.1).
